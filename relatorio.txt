Atividade 11 - Compilador Fun (Funções)
=======================================

O objetivo desta atividade foi estender o compilador da atividade 10 para suportar a
linguagem Fun, adicionando funções, parâmetros, variáveis locais e o bloco principal
identificado pela palavra-chave main.

Principais mudanças implementadas:

1. ANALISE LEXICA (lexer.go, token.go)
   - Novos tokens: , fun var main
   - Novas palavras-chave reconhecidas: fun, var, main
   - O restante do comportamento do lexer foi mantido

2. ANALISE SINTATICA (parser.go)
   - Novo formato do programa: decl* main { cmds* return exp; }
   - Declarações podem ser de variável global ou função
   - Declarações de variável agora usam a forma var x = exp;
   - Funções são reconhecidas com lista de parâmetros formais opcional
   - Chamadas de função são reconhecidas como expressões primárias
   - O parser usa lookahead de 1 token para diferenciar referência a variável de chamada

3. AST E INTERPRETE (ast.go)
   - Novos nós: Call, VarDecl, FunDecl
   - Programa passa a armazenar uma sequência de declarações mais o bloco principal
   - O intérprete agora possui:
     * ambiente global
     * ambiente local por chamada de função
     * parâmetros tratados como variáveis locais
     * busca local-primeiro e depois global
     * suporte a recursão direta

4. ANALISE SEMANTICA (semantic.go)
   - Tabela global distingue variáveis globais e funções
   - Cada função é registrada antes da análise do próprio corpo, permitindo recursão direta
   - Chamadas verificam:
     * se a função existe
     * se o símbolo é realmente uma função
     * se a quantidade de argumentos corresponde à aridade declarada
   - Variáveis em funções são resolvidas consultando primeiro o escopo local e depois o global
   - Símbolos duplicados no mesmo escopo são rejeitados
   - Chamadas para funções declaradas apenas depois do ponto de uso continuam sendo rejeitadas
   - Recursão mútua não foi implementada

5. GERACAO DE CODIGO (codegen.go)
   - Variáveis globais continuam na seção BSS
   - O bloco principal permanece em _start
   - Cada função gera:
     * rótulo com o nome da função
     * prólogo com push %rbp, alocação dos locais e mov %rsp, %rbp
     * inicialização das variáveis locais
     * código dos comandos
     * cálculo da expressão de retorno em %rax
     * epílogo com desalocação, pop %rbp e ret
   - Chamadas de função:
     * avaliam argumentos da direita para a esquerda
     * empilham os argumentos
     * usam call nome
     * limpam a pilha após o retorno
   - Parâmetros e locais são acessados por deslocamento relativo a %rbp
   - Acesso a globais usa endereçamento relativo a %rip

6. TESTES
   - Testes unitários Go para:
     * novos tokens
     * parsing de funções e chamadas
     * distinção entre variável e chamada
     * semântica de funções e aridade
     * sombra de globais por locais/parâmetros
     * recursão direta
     * inspeção do assembly gerado
   - Programas .fun em tests/ cobrindo:
     * variável local
     * função sem parâmetros
     * chamada encadeada
     * sombra de variáveis
     * recursão direta
     * erros semânticos de função

Como executar:
  go test ./...

No Linux/WSL:
  sh run_tests.sh

Exemplo manual:
  go build -o cmd .
  ./cmd tests/fact.fun
  as -o tests/fact.o tests/fact.s
  ld -o tests/fact tests/fact.o
  ./tests/fact
